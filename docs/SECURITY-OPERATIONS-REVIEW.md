# 보안·운영 점검 — 2026-09-18

RTX 4060 서버에서 0.2.5 후보를 검사했다. 초대 고객 확대와 불특정 사이트 등록의 승인 문서가 아니다. 실제 클라우드 브라우저 재검증, 네트워크 계층의 IP 격리, 외부 검토는 별도 조건이다.

## 확인한 항목

| 항목 | 실행한 시험 | 결과 |
|---|---|---|
| 고객 격리 | 다른 고객의 보고서·이미지·목록·취소·삭제·실행, 만료·폐기 키, 잘못된 Origin | Node Request 처리기와 실제 로컬 workerd/D1에서 차단 |
| 네트워크 | 사설/혼합/빈 DNS 응답, URL 변형, 주소 변경, HTTP 리디렉션, WebSocket | 아래 수정 후 로컬 시험 통과 |
| 중단 | 실행 전 연결 종료, 실행 중 키 폐기, 취소 후 늦은 결과 저장, 수정된 요청 | 실행 또는 결과 저장 차단 |
| 저장 장애 | 성공 직후 DB 저장 실패와 중단 기록 저장 실패 동시 주입 | 503 반환, 복구 시 inconclusive, 자동 재실행 없음 |
| 삭제·보존 | 결과와 이미지 동시 삭제, 7일 경과 삭제, 8일 경과 잔여 기록 제거, 트랜잭션 실패 | 합성 SQLite 데이터에서 확인 |
| 복원 | 삭제 전 SQLite 백업을 실제 파일로 복원하고 격리 절차 적용 | 모든 기존 키 비활성화, 과거 보고서·이미지 제거, 실행 재개 없음 |

전체 테스트 31개 통과. 추가 보안·운영 테스트 13개가 포함된다. 로컬 workerd/D1 HTTP 시험은 12건 통과했다. 시험용 복구 외에 운영 DB를 복원하거나 고객 데이터를 변경하지 않았다.

## 재현 후 수정

1. DNS 성공 결과를 브라우저 수명 동안 재사용하여 이후 사설 주소 응답을 놓쳤다. 요청마다 재확인한다. DNS 확인과 실제 접속 사이의 주소 변경까지 막는 IP 고정은 아니다.
2. WebSocket은 HTTP 요청 경로의 검사만으로 통제되지 않았다. 업스트림에 연결하지 않고 닫는다. 현재 WebSocket 여정은 미지원이다.
3. 실제 Chromium에서 HTTP 302 응답 이후 로컬 시험 서버의 차단 대상에 요청이 도착했다. 요청을 `route.fetch({maxRedirects:0,maxRetries:0})`로 보내고 3xx 리디렉션을 거부한다. 최종 HTTPS 주소를 직접 등록해야 한다. 정상적인 로그인·리디렉션 여정도 현재는 확인 불가가 될 수 있다.
4. 연결 종료 이전 상태 확인, 실행 중 키 폐기 감지, 결과 저장 시 고객 활성 상태 확인을 추가했다. 저장 장애를 입력 오류 400으로 표시하지 않는다.
5. 네트워크 정책으로 막힌 요청이 있으면 다음 쓰기 동작을 중단하고 전체 판정을 inconclusive로 표시한다. 환경 제한으로 발생한 불일치를 사이트 결함으로 확정하지 않는다.

Cloudflare 세션에도 정확한 호스트 목록을 전달한다. 이 기능은 [Cloudflare의 HTTP/HTTPS 호스트 제한](https://developers.cloudflare.com/browser-run/features/guardrails/)이며 사설 IP 차단의 완전한 증거로 취급하지 않는다. 리디렉션을 따르지 않는 옵션은 [Playwright 공식 API](https://playwright.dev/docs/api/class-route#route-fetch)를 사용한다.

## 복구 절차

1. 장애 시 신규 접수를 중지한다. 실패한 쓰기 동작을 자동 재실행하지 않는다.
2. DB 복원본은 서비스와 분리한다. 복원 전 삭제·키 폐기 기록이 복원본에 없을 수 있다.
3. `cloud/src/restore-policy.mjs`의 `quarantineRestoredDatabase`와 동일한 원자적 처리를 적용한다: 모든 초대 키 비활성화, 모든 실행을 삭제 상태로 전환, 보고서·이미지 제거. 과거 보고서를 복구하지 않는 보수적 정책이다.
4. 복원본의 활성 키·진행 중 실행·보고서·이미지가 모두 0인지 확인한 다음 서비스에 연결한다. 기존 키를 그대로 다시 활성화하지 않고 새 키를 발급한다.
5. 정상·차단 여정과 고객 격리를 확인한 뒤 초대 고객의 접수를 재개한다. 운영 Cloudflare D1 복원 훈련은 아직 수행하지 않았다.

## 남은 배포 조건

- 0.2.5의 실제 Cloudflare 기본·여정 검사 및 세션 호스트 차단을 확인해야 한다. 0.2.4의 과거 통과를 새 버전의 증거로 사용하지 않는다.
- 지금까지 확인한 일일 전역 실행 4회는 모두 사용했다. 한도를 초기화하거나 우회하지 않는다.
- 사전 DNS 확인과 실제 연결의 TOCTOU, WebRTC 등 비 HTTP 전송의 플랫폼 격리는 입증되지 않았다. 임의 도메인·임의 HTML 입력을 고객에게 개방하지 않는다. 운영자가 검토한 테스트 사이트만 유지한다.
- 로컬 SQLite 복원 시험은 Cloudflare 운영 DB의 복구 시간·복원 성공을 입증하지 않는다.

이 조건이 남아 있으므로 2번은 **로컬 점검·수정 완료, 클라우드 운영 검증 미완료**다.
